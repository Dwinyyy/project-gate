# Twelve invariant ownership assignments

Source: Brief §25. Owners are domain responsibilities, not claims of implementation. Each invariant must be enforced at authoritative boundaries, exercised under concurrency/failure where relevant and reviewed before public lethal play.

| ID  | Invariant                                                                                                                  | Owner / collaborators                     | Intended enforcement                                                                         | Acceptance links    |
| --- | -------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------- | -------------------------------------------------------------------------------------------- | ------------------- |
| I01 | One account has at most one living character, and no new one during active death cooldown.                                 | lifecycle / identity                      | Account lock, partial living-character uniqueness, server eligibility transaction            | A01,A02,A21,A27     |
| I02 | A permanently dead character cannot act, trade, vote, earn active rewards or regain old authority.                         | lifecycle; all command domains            | Death authority barrier and operation-specific authorization inside commit                   | A18,A19,A25,A27,A28 |

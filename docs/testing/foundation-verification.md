## Limitations

The hosted preview is an account-enabled foundation shell, not a playable game. A clean deployed registration → email verification → password sign-in → refresh → recovery-only restriction → password update → sign-in-page notice → explicit sign-in checkpoint remains pending after this fix. No provisioned operator identity has completed sign-in → TOTP enrollment → AAL2 grant check → sign-out. The current recovery UI lacks the TOTP step-up required by Supabase for password updates on already-MFA-enrolled accounts; that functional gap must be resolved and tested before Task 2.1 acceptance.

Direct Supabase account-management endpoints follow provider policy independently of our UI. Email compromise still permits password recovery; protect the inbox with MFA. Global sign-out revokes refresh sessions but previously issued access tokens follow provider expiry/revocation behavior. DevTools cannot be disabled as a security boundary, and these checks cannot promise zero vulnerabilities. Characters, gameplay, economy, location and mobile packaging are not implemented. A01–A28 gameplay cases remain not-run. PostGIS belongs with geographic queries.
